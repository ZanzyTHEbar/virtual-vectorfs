# Local Agent — F1 Default Scope and Recovery Policy

**Decision:** The user delegated F1 choices to conservative defaults on 2026-10-11. This is the policy contract for the planned **separate companion product**, not an implemented security feature of the search library. The [delivery plan](LOCAL_AGENT_PLAN.md) owns work order and completion gates. Changes to these defaults must be reviewed there before a write capability is enabled.

## Authority and roots

- Start with **no blanket access to `$HOME`**. The app workspace is the only initial root; add external read roots only when selected by the user. Never infer a read grant from a search hit. Known credentials, configuration secrets, and private key directories are excluded from ordinary grants. Path exclusions are not a reliable secret detector; an approved document may itself contain sensitive text.
- The only default writable root is a **new, initially empty, app-owned workspace** under `${XDG_DATA_HOME:-$HOME/.local/share}/local-agent/workspace`. No pre-existing personal directory gets a write grant. An environment-derived path is only a candidate: at initial adoption, require an empty workspace; on every start, require absolute paths, trusted user ownership, safe ancestry with no symlinks, and a match to the recorded workspace identity. Reconcile its contents after restart; do not require it to remain empty. Reject privileged broker execution and unsafe pre-existing paths. Journal, backups, search index, and tool-result storage live outside indexed/readable workspace roots under `${XDG_STATE_HOME:-$HOME/.local/state}/local-agent/`, subject to the same path checks.
- W3 initially supports **create-new regular files in existing workspace directories only**; W3a adds creation of new directories after its own gate. The broker refuses overwrites, traversal, symlinks in path components, mount crossings, hardlinked existing targets, special files, arbitrary shell commands, and writes outside its root. Replace/delete/same-filesystem move remain denied until their separate W5–W7 gates pass. **Cross-device moves (W8) are disabled** under these defaults; enabling one requires reviewed grants for both local filesystems. A read grant is not a write grant.
- Enable a write capability only on a locally tested Linux filesystem with the required no-replace, flush, and recovery behavior. An unknown, network, or unsupported filesystem stays read-only. One broker process owns effect execution; model calls and Goja can only propose actions.

## Version checks and honest undo

- Approval is single-use and binds the exact plan, root, paths, operation, expected source version, and expiry. Before every effect, flush the intent and required recovery data, and stage/flush any preimage or new content before publication. Recheck preconditions, but treat failed effect or directory flush as an uncertain outcome to reconcile by operation ID on restart; never blindly retry it. A free-space check is not a durability guarantee, including when journal and workspace are on different filesystems.
- An agent-created file can be removed on undo **only after checking that its identity and current content still match the recorded postimage**. A detectable mismatch is a conflict; leave it untouched. This check alone does not protect against a concurrent non-cooperating writer between check and removal. Later replace/delete/move operations must save and flush a preimage before affecting a user file, then restore only under their version conditions. Multi-operation undo is reverse-order compensation, not an atomic filesystem transaction.
- A supported rollback means restoring recorded bytes, path, permissions, and modification time **where that operation promises and verifies them**. Inode identity, creation/change timestamps, arbitrary ACLs/xattrs, open file handles, and writes by other applications are not recoverable by this policy. Refuse an operation if it cannot preserve metadata it promises to restore.
- Other programs may edit files **between** broker operations. A changed version invalidates approval or undo and becomes a conflict. A check followed by rename/delete is not an atomic compare-and-swap against a non-cooperating process: there is **no guarantee against a same-UID adversarial writer racing during an effect or undo**. Such roots are not eligible for destructive operations under these defaults; do not advertise unconditional or exact rollback.

## Capacity, privacy, and local inference

- Default maximum written file: **8 MiB** (below the search library's default 10 MiB indexing limit; non-text content may still be unindexable). Retained undo evidence: **1 GiB total**; private tool-result/transcript payloads have a **separate 1 GiB cap**. Refuse new operations or tasks at capacity or if staging, preimage, and journal writes cannot be completed; do not silently evict backups or results. **No automatic expiry:** reversible evidence and replayable payloads remain until the user explicitly prunes them, at which point affected undo or replay is visibly unavailable. Keep immutable audit records of these decisions; audit metadata itself is admission-controlled rather than assumed to fit forever.
- Private state directories use `0700`, files `0600`, and a restrictive umask. Model prompts, tool results, preimages, and transcripts can contain personal data; do not put raw content in ordinary diagnostics or assume local-only means secret-safe. These permissions do **not** protect against other processes running as the same user.
- Initial inference limits: one active generation, one embedding job at a time, at most **8K total context tokens**, **1,024 output tokens per call**, **four model calls per task**, **two minutes per call**, and **ten minutes per task**; recursion stays depth one with fan-out one and tool-result previews stay bounded. The model endpoint binds to loopback and runtime outbound network access is denied. R1 must measure actual model compatibility, RAM/VRAM, and latency before enabling it; these ceilings are limits, not performance promises or proof that a model fits.

## Acceptance boundary

F1 records user-delegated policy choices; **no workspace write is authorized by this document alone**. W1–W3 must demonstrate durable intent and preimage handling, collision refusal, symlink/mount checks, disk-full and crash recovery, idempotency, and conditional undo on an actual supported filesystem. Every later write type repeats those gates. A detected conflict is a safe outcome; silent overwrite or lost recovery evidence is not.
